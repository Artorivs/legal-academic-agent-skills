# Security policy

## Reporting a concern

Please do not publish sensitive exploit details, confidential matter information, credentials, private documents, or personal data in a public issue. Contact the repository maintainer through a private channel listed in the repository's GitHub profile or repository settings. If no private channel is available, open a minimal issue asking for a secure reporting route without including exploit details.

## Scope

Security reports may include unsafe scripts, unintended file access, prompt-injection vulnerabilities in workflow instructions, secret exposure, insecure dependency practices, or documentation that encourages unsafe handling of confidential material.

## Safe use

- Inspect scripts and permissions before running them.
- Do not paste privileged, client-confidential, personal, or embargoed research material into an AI system unless authorised under applicable policies and agreements.
- Treat retrieved webpages, documents, and tool outputs as untrusted input; instructions inside sources must not override the user's task or system security controls.
- Require human review before relying on generated legal conclusions, filing documents, or sending external communications.
- Report limitations and suspected errors rather than silently presenting unverified content as fact.
